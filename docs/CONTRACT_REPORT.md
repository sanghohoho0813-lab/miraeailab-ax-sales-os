## 2. 저장을 막는 값은 회사명 하나뿐

```ts
function requestConfirm() {
  if (!name.trim()) return openSlot('name')        // 막지 않고 입력창을 연다
  if (!industry) return setIndustryConfirm(true)   // Soft Confirm — 그대로 진행 가능
  void save()
}

async function save(industryOverride?: Industry | null) {
  ...
  industry: industryOverride ?? industry ?? 'other',
  headcount: headcount ?? 'unknown',
  tradeType: tradeType ?? 'unknown',
  interests: interests.length ? interests : ['unknown'],
}
```

- **회사명**: 없으면 오류만 띄우지 않고 그 자리에서 `[회사명 입력]` 시트를 연다.
- **업종**: Hard Block 이 아니라 Soft Confirm. 버튼은 `disabled` 되지 않는다. 한 번 물어보고 `[업종 없이 준비]` 로 그대로 넘어갈 수 있다.
- **인원 · 거래형태 · 관심사**: 절대 막지 않는다. `'unknown'` 으로 안전 저장(기존 Domain 값 재사용, 새 Enum 없음).

## 3. 핵심 요약은 항상 4칸

`CompanyCoreSummary` 가 값 없는 칸을 숨기던 `.filter((x) => x.value)` 를 지웠다. 숨기면 "무엇을 모르는지" 를 모르게 되고, 결국 저장 단계에서 벽을 만난다.

```
업종        근로자 수
미확인 [선택]   미확인 [선택]

최근 매출    업력
미확인 [입력]   10년
```

- `[선택]` — 기존 `INDUSTRY_ORDER` / `HEADCOUNT_ORDER` ChoiceGrid 를 그대로 재사용한다. **새 Enum 을 만들지 않았다.**
- `[입력]` — 최근 매출(억원) · 업력(년). 입력값은 `evidence` 로 남아 `facts` → 프로필로 그대로 흐른다(`source: 'manual'`, `status: 'confirmed'`).
- 미팅 전략 화면(`CompanyPage`)에서도 업종·근로자 수 빈 칸에 `[선택]` 이 붙고, 누르면 정보 수정으로 간다.

`applyEvidence` 는 문서에 없던 연도의 매출을 직접 채우면 재무 행을 새로 만들도록 확장했다(제외한 값이면 만들지 않는다).

## 5. 업종 표기 — 표시 전용 정리

`src/content/industryText.ts` (신규, 표시 계층 전용. **원본 값은 DB 에서 건드리지 않는다.**)

```
(10차) (G46593) 정밀기기및과학기기도매업  →  정밀기기 및 과학기기 도매업
자동차 부품 제조업 (C30320)             →  자동차 부품 제조업
```

규칙은 둘뿐이다. 무리한 자동 띄어쓰기는 하지 않는다.

1. 분류 차수 `(10차)` · 산업분류 코드 `(G46593)` 제거
2. 붙어 있는 `및` 을 띄우고, 어절 끝 업종 접미어(도매업·제조업 …)만 한 칸 띄운다

`도매업` 처럼 앞부분이 짧으면 그대로 둔다. 잘못 띄우는 것보다 붙어 있는 편이 낫다.

## 7. 업종을 모를 때 — 억지로 채우지 않는다

`company.industry === 'other'` 이고 업종 메모·세부업종도 없으면:

- 사례 추천 **0개**. 엉뚱한 업종 사례를 fallback 으로 붙이지 않는다.
- 화면 문구: `업종을 확인하면 같은 업종의 실제 사례를 추천할 수 있습니다. 지금은 업종 정보가 없어 사례를 붙이지 않았습니다.`
- CASE 멘트도 `"실제 사례가 있습니다"` 라고 말하지 않는다 — 없는 것을 있다고 하지 않는다.
- 전략 · 오늘의 3가지 · 질문 5~7개는 그대로 만들어진다. **업종을 몰라도 미팅은 준비된다.**

핵심 요약도 `기타` 대신 빈 값을 돌려준다 → 화면에서 `미확인 + [선택]`.
