## 0. 왜 이걸 먼저 했나

Request 7 에서 사례를 2개 → 5개로 늘린 뒤 **실제로 재어 봤더니 주 동작이 화면 밖으로 밀려났다.**
정보를 늘리는 것이 목적이었지, [미팅 시작]을 묻는 것이 목적이 아니었다. 추측이 아니라 측정으로 확인하고 되돌렸다.

```
모바일(390×839) 미팅 전략 화면
  전       문서 2,445px = 2.91 화면   ·  [미팅 시작] 상단이 2,014px (2.40 화면 아래)
  후       문서 1,991px = 2.37 화면   ·  [미팅 시작] 상단이   738px (0.88 화면)
데스크톱(1366×900)
  전       1.87 화면 · CTA 상단 1,391px (1.55 화면 아래)
  후       1.57 화면 · CTA 상단   639px (0.71 화면 — 첫 화면 안, 가림 없음)
```

**모바일은 "첫 화면 안" 이라고 말하지 않겠다.** 하단 내비(64px)가 775px 부터 덮으므로,
버튼(738~794px)은 **위쪽 2/3 가 보이고 아래 1/3 이 내비에 가린다.** 손가락 한 번만 밀면 완전히 드러난다.
2.40 화면 아래에 묻혀 있던 것과는 완전히 다른 상태지만, 완전한 노출은 아니다 — 남은 과제로 §8 에 적었다.

## 1. [미팅 시작]을 사례 위로

화면 순서를 바꿨다.

| 전 | 후 |
|---|---|
| 핵심 4 → 오늘 3가지 → **사례 5개** → [미팅 시작] | 핵심 4 → 오늘 3가지 → **[미팅 시작]** → 사례 |

근거: Partner 가 이 화면에서 하는 일은 "훑고 들어가기" 다. 사례는 미팅 중에 꺼내는 카드이지 시작을 막는 관문이 아니다.
LIVE 화면을 확인해 보니 사례를 화면에 띄우지 않으므로(분석에만 쓴다) 준비 화면에서 훑는 것이 맞고, 그렇다고 CTA 아래로 내려갈 이유는 없다.

## 2. 사례는 기본 3개 + [2개 더 보기] — 그리고 정렬을 바꿨다

5개를 한 번에 펼치면 모바일에서 화면 한 장이 사례로만 찬다. **계산은 그대로 5개**(10억 이내 ≥3 · 수십억 ≤2 규칙 유지), 화면에만 3개를 펼치고 나머지는 버튼 한 번으로 연다.
데스크톱 `xl` 3열에서는 기본 3개가 정확히 한 줄이 된다.

**E2E 가 여기서 진짜 문제를 잡았다.** 3개만 펼치자 제조 업종에서 먼저 보이는 3개에 10억 이내가 **1개뿐**이었다.
Request 7 은 "조합은 무엇이 들어가나를 정하고 순서는 점수(얼마나 비슷한가)가 정한다" 였는데, 5개를 다 보여줄 때만 성립하는 원칙이었다.
먼저 보이는 3개에 10억 이내가 1개면 "5개 중 3개는 10억 이내" 규칙이 화면에 없는 것과 같다.

→ `composePicks` 가 **점수순을 유지한 채 10억 이내를 앞으로** 내보내도록 바꿨다(stable). 5~30명 회사 대표 앞에서는
"가장 비슷한 사례" 보다 "우리 규모 얘기" 가 먼저 와야 설득이 된다. 10억 이내가 없는 업종(물류)에서는 순서가 그대로다.

## 3. PDF 검토 — 하단 CTA 가 마지막 내용을 덮던 문제 (R6 §11 이월)

`sticky` 는 자기 자리를 flow 에 남기고 떠오른다. 바로 아래에 여유가 없으면 문서 끝까지 내려도 바가 마지막 내용 위에 앉는다.

```
전   미팅 시각 줄 하단 831px  vs  CTA 상단 664px   →  168px 겹침 (영구히 가림)
후   마지막 요소 하단 496px  vs  CTA 상단 537px   →  41px 여유
```

고친 방법: 바 아래에 모바일 전용 spacer(5.5rem + safe-area) 한 줄. 끝까지 내리면 바가 제자리에 앉아 아무것도 가리지 않는다.
`setTimeout` 이나 스크롤 조작이 아니라 레이아웃으로 풀었다.

## 4. 홈 시계 중복 제거

Request 6 에서 글로벌 헤더가 어느 폭에서나 날짜·요일·초 단위 시각을 갖게 됐다. 홈이 같은 것을 한 번 더, 그것도 KPI 크기로 보여 주고 있었다.
홈에서 날짜 줄과 큰 시계를 빼고 인사말 → 오늘 미팅 N건 → [미팅 준비 시작] 으로 정리했다. 첫 화면에서 주 동작이 더 위로 올라온다.

## 5. 업종별 사례 커버리지 (마스터 · 사용 데이터)

Request 7 에서 **물류는 10억 이내 검수 사례가 0건**이라 규칙을 지킬 수 없다는 것을 발견했다. 이건 코드가 아니라 데이터 문제다 —
타업종을 끌어오는 순간 "광고회사에 화훼 사례" 가 돌아온다. 그래서 **어디를 리서치해야 하는지 마스터가 화면에서 보도록** 했다.

`/master/usage` 에 읽기 전용 표 하나를 더했다(새 페이지·새 대시보드 아님).

| 업종 | 검수 사례 | 10억 이내 | 상태 |
|---|---|---|---|
| 물류 | 9 | 0 | **없음 — 3건 더 필요** |
| 건설 | 17 | 6 | 충분 |
| … | | | |

부족한 업종이 위로 정렬된다. 추천 품질의 상한선이 무엇인지 숫자로 보인다.

## 8. 남은 것

- **물류 10억 이내 사례 3건 리서치 추가** — 이제 마스터 화면이 이 공백을 매일 보여 준다.
- **모바일 [미팅 시작] 을 하단 내비 위로 완전히 올리기** — 약 40px 이 모자란다. 후보: "오늘은 이 3가지만" 행 높이(현재 3행 × 약 70px), 핵심 카드에서 업종이 두 줄로 감싸지는 것, 상단 [고객 · 정보 수정 · 휴지통] 행.
  이번에는 손대지 않았다. 검증된 개선(2.40 → 0.88 화면)을 지키는 쪽이 낫고, 여백을 몇 px 씩 깎는 작업은 효과 대비 회귀 위험이 크다.
- 모바일 전략 화면 2.37 화면. Request 5 목표(1~1.5)에는 아직 못 미친다. 사례 카드 본문 줄 수가 다음 후보다.
- `최근 매출` 직접 입력이 억원 단위 고정 — 1억 미만 고객에는 단위 선택이 필요할 수 있다.
